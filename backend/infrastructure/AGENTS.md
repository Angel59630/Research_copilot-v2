# 基础设施模块设计

## 1. 职责

基础设施模块集中提供配置、SQLite 会话与迁移、Chroma、文件存储、后台执行器、DeepSeek、Ollama、MCP Client、日志、错误映射和健康检查等技术适配器。

## 2. 配置

根目录 `config.py` 是唯一配置入口，`.env` 只保存敏感值。业务模块只依赖类型化配置对象，不直接读取环境变量。

配置覆盖：

- 服务地址、端口、CORS。
- 数据与日志路径。
- PDF 限制。
- 后台并发、超时和重试。
- DeepSeek 动态模型列表。
- Ollama 与 `bge-m3`。
- RAG、分块和压缩参数。
- 日志轮转参数。

前端模型配置接口只返回允许公开的字段。

## 3. 外部适配器

- DeepSeek：OpenAI 兼容客户端，支持流式输出、超时和用量读取。
- Ollama：Embedding 客户端。
- Chroma：按论文 ID 写入、过滤检索和删除。
- MCP Client：通过 stdio 管理 Arxiv MCP 子进程。
- 文件存储：根据内部 ID 解析路径，阻止任意路径访问。

## 4. 日志

- 为 REST、SSE、后台任务和内部调用传播 `request_id`。
- 输出控制台与 UTF-8 轮转文件。
- 记录路由、状态、耗时、对象 ID、阶段、模型标识和异常堆栈。
- 不记录用户问题、模型回答、论文正文、引用原文、PDF 内容、凭据或未脱敏绝对路径。

## 5. 健康检查

分别检查 SQLite、Chroma、Ollama 和 Arxiv MCP。响应只包含状态、耗时和安全错误摘要，不泄露凭据或路径。

## 6. 边界

- 基础设施实现业务模块定义的端口，不承载论文、分组、导入、RAG 或会话规则。
- 外部客户端必须显式设置超时。
- 文件与向量清理失败必须抛出可识别错误并写日志。
