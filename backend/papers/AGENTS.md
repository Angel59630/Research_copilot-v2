# 论文模块设计

## 1. 职责

论文模块拥有论文记录、可编辑元数据、标签关系和原始文件生命周期，为导入、分组、RAG 和会话模块提供稳定的论文查询接口。

## 2. 核心数据

`Paper` 至少包含：

- 内部唯一 ID。
- 来源类型与来源标识。
- 标题、作者、发表日期、摘要、备注。
- 原始文件内部路径。
- 处理状态。
- 创建时间与更新时间。

`Tag` 与论文为多对多关系。摘要字段是元数据，不代表独立 AI 摘要功能。

## 3. 公开能力

- 创建独立论文记录。
- 保存和读取原始 PDF。
- 分页查询论文。
- 按标题、作者、标签、分组、状态和来源筛选。
- 编辑元数据和标签。
- 下载原始 PDF。
- 查询论文是否可用于 RAG。
- 发起带二次确认语义的永久删除。

## 4. 删除规则

删除论文需要应用层协调：

- 删除单论文会话和消息。
- 删除标签与分组关系。
- 按论文 ID 删除 Chroma 文本块。
- 删除分页文本与原始 PDF。
- 最后删除论文记录。

任何清理失败都必须记录 `request_id`，不得静默忽略。API 不接受用户提供的任意文件路径，文件只能通过论文 ID 定位。

## 5. 边界

- 不负责 PDF 解析、分块或向量化。
- 不负责分组业务规则。
- 不负责问答和摘要生成。
- 编辑元数据不触发重新向量化。
- 每次导入均创建新论文，不去重。
