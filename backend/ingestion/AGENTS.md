# 论文导入模块设计

## 1. 职责

导入模块统一处理本地 PDF 和 Arxiv PDF 的接入、任务状态、文本提取、分页分块、Embedding 与 Chroma 写入。

## 2. 输入路径

### 本地上传

校验 PDF 类型和 50 MB 默认限制，创建论文与导入任务后立即返回，由后台继续处理。

### Arxiv 导入

通过基础设施 MCP Client 调用项目内 Arxiv MCP Server，获得元数据和 PDF；每次选择均创建独立论文记录，再进入同一处理流水线。

## 3. 任务状态

- 等待
- 解析中
- 向量化中
- 完成
- 失败
- 已中断

每次状态变化保存时间和安全错误信息。错误日志包含任务 ID、论文 ID、阶段和 `request_id`，不包含论文正文。

## 4. 处理流水线

1. 保存 PDF 并校验最多 500 个物理页。
2. 按物理页从 1 开始提取文本。
3. 检测有效文本；扫描件或无有效文本时失败，不做 OCR。
4. 保存分页文本。
5. 在页内分块，避免一个文本块跨越不同 PDF 页。
6. 调用 Ollama `bge-m3` 批量生成 Embedding。
7. 将文本块、论文 ID、页码和块 ID 写入 Chroma。
8. 标记论文和任务完成。

## 5. 重试与幂等

- 重试前按论文 ID 清除不完整向量。
- 重试复用同一论文记录和已保存 PDF。
- 同一任务不得产生重复文本块 ID。
- 应用重启时将运行中任务标记为已中断，由用户手动重试。
- 后台任务并发数、超时、分块和批处理参数来自 `config.py`。

## 6. 边界

- 不负责论文去重。
- 不修改用户已编辑的元数据，除非字段尚未设置且导入源提供值。
- 不负责问答检索。
- 不引入 Celery 或 Redis。
