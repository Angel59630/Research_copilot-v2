# Agentic RAG 模块设计

## 1. 职责

RAG 模块实现受控 LangGraph 工作流，在明确的单论文或分组范围内完成检索、相关性评估、查询改写、回答生成和引用校验。

## 2. 输入与输出

输入：

- 用户问题。
- 会话范围类型与范围 ID。
- 由会话模块准备的压缩摘要和近期消息。
- 当前会话模型配置。

输出：

- 可流式传输的回答增量。
- 完成状态与模型用量。
- 经校验的引用集合。
- 安全错误，不直接写入会话数据库。

## 3. 工作流

```text
解析检索范围
→ Chroma 检索
→ 相关性评估
→ 证据不足则改写查询
→ 再次检索
→ 生成回答
→ 校验引用
```

默认最多两轮检索，`top_k`、相关性阈值和最大轮数来自 `config.py`。

## 4. 范围规则

- 单论文会话只允许检索目标论文 ID。
- 分组会话在每次提问时读取当前成员，仅保留处理完成的论文。
- 等待、处理中、失败和中断论文被静默忽略。
- RAG 不缓存分组成员快照。
- 每轮系统提示词包含范围名称，以及处理完成论文的临时编号、标题和作者。
- 分组问题未明确指定论文时，检索全部当前可用成员。
- 用户可通过完整标题、部分标题、作者或会话历史指代限定一篇或多篇论文。
- 第一版不根据摘要、正文或主题描述识别论文。
- 明确指定但无法唯一匹配时，Agent 请求澄清且本轮不检索。
- 检索工具只接受本轮临时编号，并在后端校验其对应论文属于当前允许范围。
- 临时编号和本轮论文子集不持久化。


## 5. 回答与引用

- 论文证据优先。
- 证据不足时允许增加明确标题为“模型知识补充”的内容。
- 模型知识补充不得带论文引用。
- 检索文本块先分配来源编号。
- 最终只接受本轮检索结果中存在的编号。
- 引用输出仅包含论文名称和 PDF 物理页码。
- 不生成点击链接、PDF 定位或原文高亮数据。

## 6. 边界

- 不持久化消息或会话。
- 不直接操作 PDF 文件。
- 不负责上下文压缩。
- 不向日志写入问题、回答、文本块内容或引用原文。
