# 后端应用架构设计

## 1. 模块职责

`backend/` 是 FastAPI 应用边界，负责路由注册、生命周期管理、依赖装配和跨业务模块编排。具体业务规则下沉到功能模块，通用技术能力下沉到 `infrastructure/`。

## 2. 子模块

- `papers/`：论文、标签和文件生命周期。
- `groups/`：分组、成员关系和未分类查询。
- `ingestion/`：导入任务、PDF 解析与向量化。
- `rag/`：Agentic RAG 与引用校验。
- `conversations/`：会话、消息、SSE、压缩和导出。
- `infrastructure/`：配置、持久化适配器、外部客户端、日志和健康检查。

## 3. 应用边界

- REST API 处理普通命令、查询和文件传输。
- SSE 仅用于模型回答流。
- 路由层只做输入校验、依赖获取、应用服务调用和响应映射。
- 跨模块级联操作由应用服务编排，不在数据库模型回调中隐式执行。
- 所有响应错误使用统一错误结构：错误码、中文消息、`request_id` 和安全详情。

## 4. 启动与关闭

启动顺序：

1. 加载并校验 `config.py`。
2. 初始化日志。
3. 创建必要数据目录。
4. 初始化 SQLite 与迁移。
5. 初始化 Chroma、模型客户端和 MCP Client 工厂。
6. 将遗留运行任务标记为已中断。
7. 启动应用内后台任务执行器。
8. 注册健康检查状态。

关闭时停止接收新任务，取消或标记运行任务，关闭 MCP 子进程与外部客户端，并释放数据库连接。

## 5. 约束

- 不引入 Celery、Redis 或 WebSocket。
- 不在路由中直接操作 SQLite、Chroma 或文件系统。
- 不在代码中散落可调参数。
- 不记录用户问题、模型回答或论文正文。
- 第一版不承担身份认证与多用户隔离。
