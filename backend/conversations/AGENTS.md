# 会话模块设计

## 1. 职责

会话模块拥有单论文与分组会话、消息、引用、会话级模型选择、SSE 生命周期、上下文压缩和 Markdown 导出。

## 2. 核心数据

`Conversation` 至少包含：

- 会话 ID、标题。
- 范围类型与论文或分组 ID。
- 当前模型标识。
- 累计压缩摘要。
- 已压缩到的消息位置。
- 创建与更新时间。

`Message` 保存角色、原始 Markdown、状态、时间、模型用量和结构化引用。原始消息不因压缩而删除或替换。

## 3. 会话能力

- 新建、重命名、删除和分页查询会话。
- 保存每个会话独立的模型选择。
- 切换模型只影响后续回答。
- 复制操作由前端完成，不改变数据库。
- 重新生成上一条回答。
- 导出 UTF-8 Markdown。
- 删除会话不影响论文、分组或向量。

## 4. SSE 生命周期

1. 校验会话与范围。
2. 保存或确认用户消息。
3. 检查是否需要自动压缩。
4. 调用 RAG 并转发内容增量。
5. 发送完成、错误或中止事件。
6. 仅在正常完成后保存正式模型回答与校验引用。

所有 SSE 事件携带 `request_id`。中止后的残缺模型回答不写入正式历史。

## 5. 上下文压缩

- 支持手动与自动触发。
- 默认自动阈值为 250,000 token。
- 实际阈值不得超过模型窗口扣除系统、检索和输出预留量后的安全值。
- 默认保留最近约 50,000 token 原始消息。
- 使用 `config.py` 指定的独立压缩模型，默认 `deepseek-v4-flash`。
- 压缩输入为已有摘要与较早未压缩消息。
- 成功后原子更新摘要与压缩位置。
- 失败时保持旧状态并返回错误。

## 6. Markdown 导出

导出包含会话标题、范围名称、模型信息、消息时间、正文和论文名称与 PDF 页码引用，不包含原始 PDF 或论文正文附件。
