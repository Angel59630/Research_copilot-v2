# Arxiv MCP Server 设计

## 1. 职责

封装 Arxiv 官方 API 和 PDF 下载能力，为 FastAPI 后端提供稳定的 MCP 工具，不持有业务数据库状态。

## 2. MCP 工具

至少提供：

- `search_papers`：按关键词、标题或作者搜索，支持分页和排序。
- `get_paper`：按 Arxiv ID 获取标准化元数据。
- `resolve_paper_url`：解析 Arxiv 论文链接并返回论文 ID。
- `download_paper`：下载指定论文 PDF 到宿主允许的临时目标。

工具名称和参数一经被后端使用，应保持向后兼容；破坏性修改必须同步更新 MCP Client 适配器。

## 3. 标准化数据

论文元数据至少包含：

- Arxiv ID。
- 标题。
- 作者列表。
- 摘要。
- 发表与更新时间。
- 分类。
- 论文页面 URL。
- PDF URL。

## 4. 网络与限流

- 调用 Arxiv 官方查询接口。
- 设置连接、读取和总超时。
- 连续请求遵守 Arxiv 的访问频率要求。
- 对临时网络错误采用有限次数退避重试。
- 校验下载结果是 PDF，并把大小限制交由导入模块再次执行。
- 展示或返回必要的数据来源致谢信息。

## 5. 日志与隐私

记录工具名、查询类型、结果数量、耗时、状态和宿主传入的 `request_id`。不记录完整用户查询文本、PDF 内容或本地绝对路径。

## 6. 边界

- 不创建论文记录。
- 不写入 Chroma。
- 不处理 PDF 文本。
- 不判断是否重复导入。
- 不实现 OCR。
